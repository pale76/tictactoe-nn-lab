# 設計メモ

アプリの仕様と、実験結果を読むときに知っておくべき設計上の判断をまとめる。使い方は [README](../README.md)、実験結果は [experiments.md](experiments.md) を参照。

## 1. 目的

〇×ゲームの盤面を題材に、ニューラルネットワーク（NN）が盤面と勝敗の関係を学習によってどの程度学べるかを実験する。
勝敗判定そのものが目的ではなく、学習データ数・エポック数・ネットワーク構成などを変えたときの、**未知の盤面に対する正答率の変化**を観察することが目的である。

## 2. データ

### 盤面
9マスを左上→右下の順に並べた 9 個の整数。`0`=空白、`1`=プレイヤー1（〇・先手）、`2`=プレイヤー2（×）。

```
0 1 2
2 1 0      →  (0, 1, 2, 2, 1, 0, 0, 1, 0)   ※中央の縦列がすべて 1 なので、ラベルは 1
0 1 0
```

### ラベル（正解）
盤面からルールで自動生成する（`src/tictactoe_nn/game.py`）。

| ラベル | 意味 |
|---|---|
| 0 | 未決着または引き分け |
| 1 | プレイヤー1の勝ち |
| 2 | プレイヤー2の勝ち |

### 盤面の範囲
| 設定 | 件数 | 内容 |
|---|---|---|
| 実際に現れる盤面（既定） | 5,478 | プレイヤー1先手で、空の盤面から交互に打って到達できる盤面。勝敗が付いた後は打たない |
| 全パターン | 19,683 | 0/1/2 の全組み合わせ（3^9）。ありえない盤面を含む |

「実際に現れる盤面」のラベル内訳は、0（未決着/引き分け）が 4,536、1 が 626、2 が 316 である。
終局盤面はプレイヤー1勝ち 626・プレイヤー2勝ち 316・引き分け 16 の計 958 通り（自動テストで確認している）。

「全パターン」には、両者が同時に3つ並べている盤面が含まれる。この盤面のラベルは便宜上 0 とする。

### 学習/テストの分割
- 乱数シード 42 の固定分割で、20% をテストデータ、80% を**学習プール**とする（実際に現れる盤面では、テスト 1,096 件・学習プール 4,382 件）。
- テストデータは学習に一切使わず、条件を変えても常に同じ。実験条件どうしの比較が公平になる。
- 学習データ数は、学習プールから取り出す件数を指す。学習プールの件数を超える指定は、自動で上限に調整される。
- 分割結果は [`data/sample.csv`](../data/sample.csv) の `split` 列（`train_pool` / `test`）で確認できる。

### 学習データの取り出し方
学習プールを乱数シードで並べ替え、先頭から n 件を使う。**同じシードなら、n を変えても小さい方が大きい方の部分集合になる**（入れ子）。学習データ数だけを変えた比較が公平になる。

## 3. 入力表現

| 設定 | 入力の数 | 内容 |
|---|---|---|
| ワンホット（既定） | 27 | 各マスを (空, 〇, ×) の3値のワンホットにする |
| 数値 | 9 | 0/1/2 の値をそのまま入力する |

## 4. モデルと学習

- 全結合のNN（PyTorch）。入力 → [全結合 + 活性化関数] × 隠れ層の数 → 全結合（3クラス）。隠れ層 0 層は、入力から3クラスへの線形モデルになる。
- 活性化関数: relu / tanh / sigmoid / leaky_relu
- 損失: クロスエントロピー、最適化: Adam
- 既定値: 隠れ層 2 層 × 64 ユニット、relu、学習率 0.001、バッチサイズ 64、エポック 50、学習データ 3,000 件、繰り返し 5 回
- ミニバッチの順序は、エポックごとにシャッフルする

### 複数回実行
同じ条件を n 回（既定 5）繰り返す。i 回目の乱数シードは「1回目のシード + i」で、次の3つが変わる。
1. ネットワークの初期値
2. 学習プールから選ばれる学習データ
3. ミニバッチの順序

結果は平均と標準偏差（標本標準偏差。1回のみのときは 0）で示す。

## 5. 評価と表示

- **正答率**: テストデータの正解ラベルと、NNの答え（最大確率のクラス）が一致した割合。学習データ側の正答率も、各エポックで測る。
- **基準の正答率**: 「常に最も多いクラスと答える」場合の、テストデータでの正答率（実際に現れる盤面で 83.2%）。ラベル 0 が多数を占めるため、正答率だけを見ると学習の効果を過大評価しやすい。画面では、この値を点線と文章で示す。
- **混同行列とクラス別正答率**: 行がルール上の正解、列がNNの答え。行ごとの割合を色と数字で示し、括弧内は1回あたりの平均件数。複数回実行では、混同行列を合計してからクラス別正答率を求める。
- **学習曲線**: 学習データ数ごとに、最終エポックの正答率（平均±標準偏差）を並べる。エポック数は固定なので、データが少ないほど重みの更新回数も少なくなる。

## 6. 画面（Gradio）

| タブ | 内容 |
|---|---|
| ① 学習実験 | 条件を設定して学習。正答率・損失、混同行列、クラス別正答率、履歴CSV |
| ② 学習データ数と正答率 | 学習データ数を変えて、学習曲線を作る。数値のCSVも出力 |
| ③ 盤面を判定 | 3×3のドロップダウンで盤面を入力。ルール上の正解、NNの答えと確率、その盤面が学習に使われたか、判定に使ったモデルの条件を表示 |

タブ③は、直前にタブ①で学習した**繰り返しの1回目のモデル**を使う。

### CSVの列

**エポックごとの履歴（タブ①）**: `run`, `seed`, `epoch`, `train_loss`, `test_loss`, `train_acc`, `test_acc`, および実験条件の列（`epochs`, `hidden_layers`, `units`, `activation`, `lr`, `input_repr`, `batch_size`, `n_runs`, `board_set`, `n_train_requested`, `n_train_used`, `base_seed`）。

**学習曲線（タブ②）**: `n_train`, `n_runs`, `train_acc_mean`, `train_acc_std`, `test_acc_mean`, `test_acc_std`, および実験条件の列。

## 7. 既知の制約

- 学習データ数の比較（学習曲線）は、エポック数を固定して行うため、「データ不足」と「更新回数の不足」が混ざる。
- テストデータは 1,096 件で、そのうちプレイヤー2の勝ちは 65 件しかない。クラス別正答率（特にプレイヤー2の勝ち）は、1件の違いで大きく動く。
- 「実際に現れる盤面のみ」と「全パターン」では、テストデータの中身が異なるため、正答率を直接比較できない。
- 実験は1つの分割（シード 42）での結果である。別の分割で同じ傾向になるかは確かめていない。
- Google Colab では、Gradio が自動で公開リンクを作ることがある。
- グラフの日本語表示には、日本語フォントが必要。見つからない環境では、ラベルが英語に切り替わる。
